# AI 생성 중 캔버스·로드맵 애니메이션

구현일: 2026-11-17

## 동작

- 생성 중 캔버스와 로드맵의 본문 영역 안에서 각각 독립적인 설계 장면을 표시한다.
- 캔버스는 입체 격자 작업대 위에서 로봇과 설계 도구가 블록을 배치하고 연결선을 그린다.
- 로드맵은 컨베이어 위에서 단계 카드가 순서대로 들어오고 도장 장치가 이동하며 단계를 조립한다.
- 두 장면의 형태와 동작을 구분하며, 기존 화면의 밝은 녹색 계열과 상자 크기에 맞춘다.
- 전체 화면 모달, 장면 접기·재열기 버튼은 사용하지 않는다.
- 첫 생성과 재생성 모두 장면을 표시하고, 성공·실패 시 해제한다.
- 재생성 중 기존 그래프·로드맵은 아래에 마운트된 상태로 유지한다.
  실패하면 기존 편집, 선택, 캔버스 위치와 로드맵 스크롤로 돌아간다.
- 생성 상태와 실제 경과 시간은 화면 상단에 작은 배지로 표시한다.
  패널 내부의 생성 안내 바와 중복 배지를 제거해 애니메이션 영역을 넓힌다.
- 함께 보기, 그래프·로드맵 집중 보기에서도 표시되는 패널에 맞춰 장면과 안내를 유지한다.
- 프로젝트·버전 조회 및 저장에는 생성 장면을 표시하지 않는다.
- SVG가 본문 영역 크기에 맞춰 축소되며 모바일에서도 상자 밖으로 넘치지 않는다.
- 운영체제의 움직임 줄이기 설정에서는 완성된 장면을 정지 상태로 표시한다.

## 구현 범위

GIF 파일이나 추가 패키지 없이 SVG·CSS 애니메이션을 사용한다.
기존 `pendingOperation.kind === "generate"` 상태에 연결하며 API·DB 계약은 변경하지 않는다.
서버 응답은 완료된 결과를 한 번에 받으므로 장면은 대기 상태를 표현한다.
실제 중간 결과·진행 단계·진행률로 표시하지 않으며 예시 블록과 단계는 저장 데이터에 포함되지 않는다.
그래프와 로드맵의 본문을 유지하는 컨테이너 안에 장면을 배치해 생성 전후의 화면 위치와 데이터를 보존한다.

## 검증

- Web 단위 테스트 87개, TypeScript 검사, ESLint 통과.
- 로딩·복구, 전체 읽기, 화면 배치 관련 브라우저 E2E 24개 통과.
- 애니메이션 두 시점에서 캔버스의 블록·설계 도구와 로드맵의 카드·도장 동작을 확인했다.
- 첫 생성·재생성, 성공·실패 후 장면 해제, 기존 편집 및 화면 위치 보존, 집중 보기 전환을 확인했다.
- 1600×1000, 1024×768, 390×844 화면에서 두 SVG와 장면의 경계, 가로 넘침과 움직임 줄이기를 검증했다.
- 실제 AI 호출이나 개인 프로젝트 변경 없이 API fixture로 검증했다.
- 데스크톱·작은 화면·모바일 캡처를 직접 확인했다.
