# 로딩 구분과 실패 복구 — 2026-10-21

재생성이 실패하면 기존 계획이 화면에서 사라지고, 프로젝트·버전 조회도 생성 중으로 보이던 문제를 수정했다.
현재 화면과 입력을 보존하고 실패한 작업을 사용자가 명시적으로 다시 시도할 수 있게 한다.

## 동작

- 프로젝트 목록·프로젝트·버전 조회, AI 생성, 버전 복원의 진행 상태를 구분한다.
  캔버스의 작은 상태 안내에 실제 경과 시간을 표시한다. 진행률과 예상 완료 시간은 만들지 않는다.
- 재생성·버전 조회 중 기존 그래프와 로드맵을 유지한다. 처리 중에는 입력·편집·저장·중복 생성을 막는다.
- 생성·버전 조회가 실패해도 기존 결과, 노드 선택, 미저장 편집과 입력, 결과 스냅샷 및 저장 기준 버전을 유지한다.
  기존 결과가 없는 최초 생성 실패에서도 입력을 보존한다.
- 오류에 원인과 **다시 시도**를 표시한다. 조회 실패는 해당 프로젝트·버전을 조회하고,
  생성 실패는 현재의 유효한 입력으로 다시 생성한다. 생성 버튼과 재시도는 같은 입력 조건을 검사한다.
- 기존 결과가 있으면 **기존 결과 유지**와 닫기 아이콘을 표시한다.
  모바일에서도 오류와 재시도를 발견하도록 실패 안내에 초점을 옮긴다.
- AI 생성 성공 후 이력 조회만 실패하면 새 결과와 버전 ID를 유지한다.
  **이력 다시 불러오기**는 이력만 조회하며 생성 요청을 반복하지 않는다.
  조회 전 버전 목록에 새 ID가 없으면 **현재 결과 · 이력 확인 필요**로 표시한다.
- 모델 목록 조회도 페이지 새로고침 없이 다시 시도할 수 있다.
- 빈 화면의 **계획 입력**은 입력란으로 이동하고, 프로젝트가 없으면 **프로젝트 만들기**가 생성 창을 연다.
- 늦은 프로젝트·버전·생성 응답은 이후 선택이나 초기화 상태를 덮어쓰지 않는다.
  이력 응답도 요청한 프로젝트·결과 문맥에만 적용한다.
- 오류 안내로 캔버스 내부 공간이 줄어들면 그래프를 다시 맞춰 노드가 잘리지 않게 한다.

복원 확인·버전 충돌 처리, 미저장 편집 이동 확인과 입력 초안 자동 저장 정책은 유지한다.
진행 중 응답을 무시하는 처리는 클라이언트 상태 보호이며 서버 작업 취소를 구현한 것은 아니다.

## 검증

- 단위 테스트 60개: 보존과 명시적 재시도, 중복 생성 차단, 성공 후 이력 조회 실패,
  늦은 응답 무시, 읽기 전용 입력, 경과 시간과 모델 재조회 등을 검증했다.
- 실제 PostgreSQL 저장·복원·동시 저장을 포함한 전체 E2E 17개 통과.
- 오류 안내 배치 보완 후 복구·배치 E2E 10개 재검증 통과.
  오류 표시 후 모든 노드가 캔버스 안에 들어오는지 확인하는 재생성 실패 시나리오도 추가 검증했다.
- TypeScript 검사, ESLint와 최종 production build 통과. 실행 중인 웹·API 정상 응답을 확인했다.
- 복구 E2E 6개는 API fixture를 사용하며 실제 AI 호출과 개인 프로젝트 변경을 수행하지 않는다.

빌드 복사본은 `build/loading-recovery-web`에 생성한다.
브라우저 보고서에 데스크톱의 기존 결과 보존과 모바일 오류 안내 캡처를 첨부한다.
