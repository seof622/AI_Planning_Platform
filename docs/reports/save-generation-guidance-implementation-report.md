# 저장 범위와 생성 조건 안내 — 2026-10-21

입력 초안은 자동 저장되지만 노드·연결·로드맵 편집은 사용자가 새 결과 버전으로 저장한다.
기존에는 영역마다 저장 버튼 이름이 달랐고, 입력 초안의 저장 여부나 생성에 부족한 입력을 확인하기 어려웠다.

## 변경한 동작

- 그래프 도구 모음, 노드 편집기와 로드맵의 버튼을 **변경 내용을 새 버전으로 저장**으로 통일한다.
  각 버튼에 **노드·연결·로드맵 편집 전체 저장** 설명을 표시하고 접근성 설명으로 연결한다.
- 헤더의 **결과 편집 저장됨 / 미저장 / 저장 중 / 저장 실패**를 입력 패널의
  **입력 초안 자동 저장 대기 중 / 저장 중 / 저장됨 / 실패**와 구분한다. 작은 화면에도 결과 저장 상태를 표시한다.
- 초안 자동 저장 실패 시 입력을 유지하고 입력 패널 안에서 원인과 **입력 초안 저장 재시도**를 제공한다.
  과거 버전을 보는 동안에는 자동 저장 일시 중지를 안내한다.
- 600ms 입력 대기 후 초안을 저장한다. 저장 요청은 순서대로 실행하고 입력 수정 번호와 프로젝트를 확인해
  늦게 도착한 이전 응답이 현재 입력을 저장 완료로 표시하거나 다른 프로젝트의 오류를 표시하지 않게 한다.
- 계획 주제, 상황·대상 1개 이상, 해야 할 일 1개 이상의 입력 조건을 명시한다.
  생성 버튼 가까이에 프로젝트·모델 상태와 다음에 채울 입력을 안내한다.
  모델이 현재 서버 제공 목록에 있는지도 확인하며 폼 제출에서도 조건을 검사한다.
- 결과가 있으면 **새 버전으로 다시 생성**을 표시한다. 현재 입력·모델과 결과 버전의 입력 스냅샷을 비교해
  **현재 입력은 아직 결과에 반영되지 않았습니다.**를 표시한다. 초안 저장 후에도 안내를 유지하고 새로고침 시 다시 비교한다.
  앞뒤 공백과 빈 반복 입력 행은 비교에서 제외한다.

## 범위와 검증

새 입력이 결과에 반영되는 시점은 AI 재생성이다. 노드·연결·로드맵 저장은 현재 결과의 편집을 저장하며
입력 변경을 AI 결과에 반영하지 않는다. API 계약, DB 스키마와 결과 버전 충돌 정책은 유지한다.
결과 스냅샷이 없는 예전 결과나 스냅샷 조회 실패 시 결과 열람을 허용하고 일반적인 재생성 안내를 표시한다.

- Web 단위 테스트 47개 통과: 필수 입력 안내, 초안 재시도, 요청 직렬화, 이전 프로젝트 응답 무시,
  초안 저장과 미반영 입력 구분, 새로고침 후 비교를 포함한다.
- Web TypeScript 검사, ESLint와 별도 소스 복사본의 Next.js production build 통과.
- 브라우저 E2E 11개 통과: 실제 PostgreSQL의 편집 저장·새로고침·복원·동시 저장,
  Markdown 다운로드, 세 가지 화면 크기와 초안 저장 실패·재시도 후 미반영 안내 유지를 포함한다.

빌드 복사본은 `build/save-generation-guidance-web`에 생성한다.
배치 테스트는 API fixture를 사용하고 저장·복원·동시 저장 테스트는 E2E 전용 프로젝트를 사용한다.
첫 전체 실행은 Docker/API가 꺼져 저장·복원 테스트를 진행하지 못했다.
Docker Desktop과 기존 API·PostgreSQL 컨테이너를 시작하고 전체 실행을 다시 수행해 통과했다.
