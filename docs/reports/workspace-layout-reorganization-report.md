# 작업 도구 위치 재배치 — 2026-10-21

왼쪽에 프로젝트 관리, 생성 이력, 그래프 편집, 내보내기와 계획 입력이 모두 쌓여
계획 입력을 찾기 어려웠다. 도구를 작업 위치 가까이 옮기고 왼쪽에는 계획 입력을 배치했다.

## 배치

| 위치 | 내용 |
| --- | --- |
| 맨 위 헤더 | 프로젝트 선택, 새 프로젝트, 저장·실행 상태 |
| 상단 작업 줄 | 결과 버전 선택, 버전 정보·비교, 과거 결과 복원, Markdown 내보내기 |
| 왼쪽 입력 패널 | 주제, 상황·대상, 해야 할 일, 접어서 보는 세부 조건과 입력 요약 |
| 입력 패널 하단 | AI 모델 선택, 모델 안내와 계획 생성 |
| 캔버스 내부 도구 모음 | 노드 추가, 연결 유형, 연결 도움말, 그래프 새 버전 저장 |
| 캔버스 아래·옆 | 로드맵 편집과 선택한 노드 편집 |

계획 유형·중요 기준·제약 조건은 **세부 조건**에서 변경한다. 접은 상태에서도 선택한
유형과 기준, 제약 조건 유무를 표시한다. 입력 요약과 초기화·오류 확인 도구도 펼쳐서 사용한다.
입력 내용의 스크롤과 모델 안내의 스크롤을 나눠 계획 생성 버튼을 패널 아래에서 유지한다.

## 펼침 창과 상태 처리

- 새 프로젝트는 헤더의 **새 프로젝트**에서 이름을 입력한다. 프로젝트가 선택되면 창이 닫힌다.
- 결과 요약·출처·생성 모델·Prompt 정보와 비교는 **버전 정보·비교**에서 확인한다.
- 과거 결과 복원과 저장 충돌 해결 버튼은 상단 작업 줄에서 바로 접근한다.
- 저장 충돌이 발생하면 경고를 표시하고 비교 정보를 자동으로 연다.
- 창은 닫기 버튼, Escape 또는 바깥 클릭으로 닫으며 키보드로 닫을 때 포커스를 되돌린다.
- 접기·펼치기는 입력과 미저장 Graph·Roadmap 편집을 유지한다.
- 프로젝트·버전 이동 시 미저장 편집 확인과 기존 저장·비교·복원 규칙을 유지한다.

## 화면 크기

데스크톱에서는 상단 두 줄과 입력·캔버스·로드맵이 화면 높이를 나눠 사용한다.
1024px 너비에서는 그래프 도구가 필요한 만큼 줄바꿈하고 노드 편집기는 오버레이로 열린다.
모바일에서는 프로젝트와 상태를 상단에 배치하고 입력 패널 아래에 캔버스와 로드맵을 쌓는다.
새 프로젝트·버전 정보 창은 모바일 화면 너비 안에 표시한다.

## 검증

- Web Vitest 39개, TypeScript 검사와 ESLint 통과.
- Playwright Chromium E2E 10개 통과. Graph·Roadmap 편집·저장·복원, 두 탭 충돌,
  PostgreSQL 동시 저장, Markdown 다운로드와 세 가지 화면 크기의 배치를 포함한다.
- Next.js production build 통과.

`npm run web:test`, `npm run web:typecheck`, `npm run lint -w apps/web`와
`npm run test:e2e`로 기존 기능과 배치를 검증한다. 배치 테스트는 API fixture를 사용하고
실제 저장·충돌 테스트는 E2E 전용 프로젝트를 생성한다.

브라우저 보고서의 `workspace-desktop`, `workspace-mobile`, `workspace-compact-desktop`에서
1440×960, 390×844, 1024×768 화면을 확인할 수 있다.
실행 중인 개발 서버를 유지하기 위해 production build는 `build/workspace-reorganization-web`의
소스·글꼴 복사본에서 수행한다.
