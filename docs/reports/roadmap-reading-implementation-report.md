# 로드맵 읽기와 선택 기반 상세 편집 — 2026-10-21

모든 단계에 입력 폼을 나열하던 로드맵을 요약 목록으로 바꿨다.
단계를 선택했을 때 오른쪽에서 해당 단계만 편집한다.

## 동작

- 목록에는 순서, 제목, 두 줄 설명, 우선순위와 선행 단계 번호를 표시한다.
  기본 화면에는 단계별 입력 폼을 표시하지 않는다.
- 선택한 단계는 목록에서 강조하고 오른쪽에 제목·설명·우선순위·작업량을 표시한다.
  관련 노드와 선행 단계는 필요할 때 펼친다.
- 노드와 단계는 같은 상세 영역을 사용한다. 선택을 전환하거나 편집기를 닫아도
  양쪽의 미저장 변경을 유지한다. 저장은 노드·연결·로드맵 전체의 새 버전을 만든다.
- 단계 추가 시 새 단계를 바로 선택한다. 순서·의존성 변경으로 번호가 바뀌어도
  ID를 기준으로 같은 단계를 계속 편집한다. 선택한 단계를 삭제하면 편집기를 닫는다.
- 기존 선행 조건의 자동 정렬, 순환 차단, 삭제 영향 확인, 참조 정리,
  저장 충돌·과거 버전·복원·생성 실패 시 편집 보존을 유지한다.
- 단계는 키보드로 선택할 수 있다. 닫기 버튼은 선택했던 목록 항목으로 초점을 돌린다.
  선택 변경·정렬 시 목록 내부만 스크롤해 페이지와 편집 위치를 유지한다.
- 넓은 화면은 오른쪽 열에서, 좁은 화면은 오버레이로 상세 편집기를 표시한다.

## 검증

- Web 단위 테스트 65개 통과: 읽기 목록, 선택 단계 폼, 저장·참조·순서·삭제,
  노드와 단계의 상호 선택 및 추가·삭제·초기화 시 선택 상태를 검증했다.
- 전체 Chromium E2E 19개 통과: 실제 PostgreSQL의 편집·참조·순서·저장·새로고침,
  버전 복원과 충돌, 생성·조회 실패 복구 및 내보내기를 포함한다.
- 10개 단계 fixture로 기본 화면의 입력 폼 부재, 키보드 선택, 편집 유지,
  닫기 후 초점 복원과 가로 넘침 방지를 검증했다.
- 1440×960 데스크톱과 390×844 모바일의 읽기·편집 화면 캡처를 확인했다.
- TypeScript 검사, ESLint와 production build 통과.
  실행 중 개발 서버를 유지하기 위해 빌드는 `build/roadmap-reading-web` 복사본에서 수행했다.

브라우저 보고서는 `playwright-report/index.html`, 실행 방법은 `tests/e2e/README.md`에 있다.
새 UI 배치 테스트는 fixture를 사용하며 AI 호출이나 기존 프로젝트 변경을 수행하지 않는다.
