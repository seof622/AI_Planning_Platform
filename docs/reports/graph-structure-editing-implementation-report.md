# Graph 구조 편집 구현 및 검증 — 2026-10-19

개인 전용 사용을 기준으로 인증·소유권과 배포 준비는 보류하고,
Graph 노드·연결 추가/삭제를 후속 기능으로 확정해 구현했다.

## 사용 흐름

1. 계획이 있는 프로젝트를 열고 왼쪽 Graph 편집에서 `노드 추가`를 누른다.
2. 열린 Node 편집 패널에서 유형·이름·설명·분류·우선순위를 수정한다.
3. 왼쪽의 `새 연결 유형`을 선택하고 Canvas의 노드 오른쪽 점을 다른 노드 왼쪽 점으로 드래그한다.
   기본 유형은 `requires`이며 자기 자신 연결과 같은 시작·끝 노드의 중복 연결은 유형에 관계없이 드롭할 수 없다.
4. 연결선이나 라벨을 클릭하면 선 옆에 유형 변경·삭제 메뉴가 열린다.
   선택한 연결선 양 끝의 원을 다른 노드로 드래그하면 출발·도착 노드를 바꿀 수 있다.
   잘못된 위치에 놓으면 기존 연결을 유지한다. Node 편집의 `노드 삭제`는 확인 후
   해당 노드와 연결, 로드맵의 해당 노드 참조를 제거한다. 로드맵 단계 자체는 유지한다.
5. `그래프 새 버전 저장`으로 구조와 기존 필드 편집을 함께 저장한다.
   Node 또는 Roadmap 패널의 저장 버튼도 같은 편집본을 저장한다.

## 저장 및 검증 규칙

- 최소 1개 노드 유지, 노드·연결 ID 중복 금지, 유한한 좌표만 허용.
- 자기 자신 연결, 같은 출발·도착 노드의 연결 중복, 존재하지 않는 노드 참조 금지.
  연결 유형이 달라도 같은 노드 쌍에 추가할 수 없으며 기존 연결의 유형만 바꾼다.
- AI 생성 결과 정규화, Shared 계약, API 편집 저장, Web 추가·재연결에 같은 중복 기준을 적용한다.
- API는 편집된 노드 집합을 기준으로 연결과 로드맵 참조를 검증한다.
- 기존 클라이언트가 `edges`를 생략하면 원본 연결을 유지한다.
- 과거 결과를 덮어쓰지 않고 새 결과에 `editedFromResultId`를 기록한다.
- 기존 최신 버전 확인·프로젝트 행 잠금·충돌 복구 흐름을 재사용한다.
- 저장 중에는 구조 변경과 Canvas 이동·연결을 차단한다.
- Roadmap 단계 추가/삭제와 내보내기는 이번 구현 범위에 포함하지 않는다.

## 검증 결과

- Web Vitest: 31개 통과. 구조 변경, 재연결·유형 변경의 중복·참조 검증, 참조 정리,
  원본 불변성, 중복·자기 연결 차단, 저장 중 변경 차단과 요청 payload를 검증했다.
- API pytest: 28개 통과. 구조 변경 저장·조회와 원본 보존, 잘못된 구조의 422 응답 및
  새 버전 미생성을 검증했다. Docker의 Python 3.13 환경에서 실행했다.
- Playwright Chromium: 4개 통과. 실제 Next.js·FastAPI·PostgreSQL에서 기존 편집,
  실제 마우스 드래그 연결·중복 드롭 차단·유형 변경·연결선 끝 재연결·삭제와 새로고침 복원,
  과거 버전, 두 탭 충돌, PostgreSQL 동시 저장을 검증했다.
- TypeScript 검사, ESLint, Shared mock contract 검증과 Next.js production build 통과.
- API 테스트에서 기존 Starlette/httpx 사용 중단 예정 경고 1개가 출력됐다.

브라우저 보고서는 `playwright-report/index.html`에 있으며 실행 방법은
`tests/e2e/README.md`를 따른다. E2E는 전용 프로젝트를 생성하고 OpenAI를 호출하지 않는다.
