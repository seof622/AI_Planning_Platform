# 편집 버전 관리 구현 및 검증

실행일: 2026-10-01. Phase 3의 출처 표시, 변경 비교, 복원과 충돌 UX를 구현했다.

## 사용자 기능

- 생성 이력에 v1·v2 번호와 AI 생성 원본, 사용자 편집본, 복원본을 표시한다.
- 편집·복원본이 어떤 버전에서 만들어졌는지 직접 출처를 표시한다.
- `버전 비교`를 열고 기준 버전을 선택하면 현재 화면과의 변경을 필드별로 보여준다.
  노드·연결·로드맵의 추가·삭제·변경과 계획 요약·요구사항을 비교한다.
- 미저장 편집도 비교에 포함한다. 저장 시각과 모델/prompt 정보는 내용 차이에서 제외한다.
- 미저장 편집 상태의 프로젝트·버전 이동, 생성·초기화와 페이지 이탈을 확인한다.
- 저장 충돌 시 작성 중인 편집을 유지하고 새 최신 버전과 비교한다.
- 사용자가 확인하면 편집본 전체를 새 버전으로 저장하거나 최신 결과를 불러온다.
  자동 병합은 하지 않으며 원본과 다른 편집 버전은 보존한다.
- 복원 충돌 시 과거 버전 미리보기를 보존한다. 재확인 후 관찰한 새 최신 버전을
  기준으로 복원을 다시 요청하며, 그 사이 또 저장되면 다시 충돌을 반환한다.

## 저장 계약과 일관성

저장·복원 요청에 `expectedLatestResultId`를 전달한다. PostgreSQL에서는 프로젝트
행을 잠근 뒤 현재 최신 ID를 확인하고 저장까지 같은 트랜잭션으로 처리한다.
AI 생성도 같은 잠금을 사용하므로 서로 다른 결과 쓰기가 직렬화된다.

충돌은 HTTP 409의 구조화된 응답으로 반환하며 새 버전이나 요구사항을 추가하지 않는다.
각 결과의 `metadata.resultId`를 반환하고, 최신 결과와 이력을 읽는 사이 저장이 발생하면
이력에 대응하는 정확한 불변 결과를 조회한다. 저장 후에도 화면에 표시한 결과의
ID를 기준으로 유지하여 다른 탭의 결과 ID를 잘못 사용하지 않는다.

출처는 현재 작업의 직접 원본만 기록한다. 편집본을 복원할 때 편집 출처를 그대로
상속하거나, 복원본을 편집할 때 복원 출처가 남는 문제를 제거했다. 기존 DB 이력은
재작성하지 않으며 기존 JSON에 resultId가 없으면 읽기 응답에만 추가한다.

본문 없는 기존 restore API 호출은 호환을 위해 유지하며 최신 ID 검사는 생략한다.
새 Web UI는 편집과 복원 모두 최신 ID를 전달한다. 자세한 계약은
`docs/planning-result-contract.md`에 있다.

## 검증

| 항목 | 결과 |
| --- | --- |
| Web 단위 테스트 | 25개 통과 |
| API 테스트 | 17개 통과 |
| 기존 Graph·Roadmap 편집 브라우저 E2E | 통과 |
| 두 탭 출처·비교·미저장 이동 취소·충돌 복구·복원 E2E | 통과 |
| PostgreSQL 동시 저장 요청 2개 | 200 응답 1개, 409 응답 1개 |
| Web 타입 검사·린트·production build | 통과 |

실제 Chromium, Next.js 15.5.22와 Docker API·PostgreSQL에서 E2E 3개를 실행했다.
테스트 fixture를 전용 프로젝트에 저장했으며 AI 호출은 없었다. HTML 보고서에는
최종 비교 화면과 저장 증빙이 포함된다. 기존 프로젝트는 수정하지 않았고, 테스트
전용 프로젝트와 버전은 DB에 남긴다. 이번 브라우저 검증은 데스크톱 Chromium 범위다.

## 직접 테스트

1. 같은 프로젝트를 두 브라우저 탭에서 연다.
2. 첫 탭에서 노드를 수정해 저장한다. 생성 이력의 편집본 출처와 `버전 비교`를 확인한다.
3. 두 번째 탭에서 노드를 수정해 저장하면 충돌 메시지와 미저장 편집 비교가 표시된다.
4. `내 편집본으로 새 버전 저장`을 확인하거나 `최신 버전 불러오기`로 변경을 버린다.
5. 과거 버전을 선택해 복원하고 복원본 출처와 기준 버전 비교를 확인한다.

다음 필수 작업은 Phase 4의 사용자 인증과 프로젝트 소유권이다.
