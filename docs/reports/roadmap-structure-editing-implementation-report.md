# Roadmap 단계·참조 편집 — 2026-10-19

기존 단계의 필드·순서 편집에 단계 추가·삭제, 관련 Graph 노드 선택과 선행 단계 설정을 추가했다.
저장한 결과는 새 planning result 버전이며 이전 버전은 그대로 남는다.

## 사용법

1. 로드맵 상단의 `단계 추가`를 누르고 새 단계의 제목·설명·우선순위·예상 작업량을 편집한다.
2. 단계 안의 `관련 노드`를 펼쳐 Graph 노드를 체크하거나 해제한다. 같은 편집본에서 추가한 노드도 선택할 수 있다.
3. `선행 단계`를 펼쳐 먼저 실행할 단계를 선택한다. 필요한 경우 전체 순서와 단계 번호를 자동 조정한다.
   순환 의존성이나 자기 참조가 생기는 변경은 적용하지 않고 기존 편집본을 유지한다.
4. 단계의 `삭제` 버튼을 누르면 선행 조건이 해제되는 단계 이름을 확인할 수 있다.
   승인하면 해당 단계와 그 단계를 가리키는 선행 참조를 제거하고 남은 번호를 정리한다.
   삭제가 다른 선행 단계로 자동 연결되지는 않는다.
5. `로드맵 새 버전 저장`을 누른다. Graph·Node 패널의 저장 버튼도 같은 편집본을 저장한다.

마지막 단계까지 삭제한 빈 로드맵도 저장·복원할 수 있고, `단계 추가`로 다시 시작할 수 있다.
수동 순서 변경은 기존처럼 선행 조건을 위반하면 차단한다.

## 저장·검증

- API의 원본 step ID 집합 유지 제한을 해제하고 단계 추가·삭제를 허용했다.
- 단계 ID 중복, 빈 제목·설명, 중복 참조, 없는 단계·노드, 순서 누락, 자기 참조·순환을 거부한다.
- 순서는 1부터 연속되어야 하고 모든 선행 단계는 현재 단계보다 앞에 있어야 한다.
- Web은 선행 단계 수정 시 기존 순서를 우선하는 위상 정렬을 수행한다. 순환이면 수정하지 않는다.
- API는 잘못된 참조를 조용히 제거하거나 순서를 바꾸지 않고 422로 거부한다.
- 저장 중에는 단계 추가·삭제·참조·필드·순서 변경을 차단한다.
- 기존 최신 버전 확인, PostgreSQL 프로젝트 행 잠금과 충돌 복구 흐름을 유지한다.
- Shared 검증도 빈 로드맵을 허용하고 단계 순서·참조 검증을 API와 맞췄다.

## 검증

- Web Vitest 36개: 단계·참조 편집 UI, 순서 자동 조정과 순환 차단, 빈 로드맵, 원본 불변성과 저장 중 변경 차단.
- API pytest 39개: 실제 저장·조회 및 빈 로드맵 복원, 잘못된 구조의 422와 버전 미생성.
- Playwright Chromium 5개: 실제 FastAPI·PostgreSQL에 연결한 신규 Roadmap 흐름과 기존 Graph·충돌 처리 회귀 검증.
- 신규 E2E는 Graph 노드와 단계 동시 추가, 노드 연결·해제, 순환 변경 거부, 순서 자동 조정,
  삭제 취소·승인·참조 정리, 새로고침, 빈 로드맵 저장·재추가와 원본 복원을 포함한다.
- 타입 검사·린트, Shared canonical fixture, 평가 fixture 9개와 평가 테스트 8개를 통과했다.
- 실행 중인 개발 서버와 분리한 임시 복사본에서 Next.js production build를 통과했다.
- 브라우저 화면은 `playwright-report/index.html`의 `roadmap-reference-editor` 첨부에서 확인할 수 있다.

테스트는 전용 프로젝트를 사용하며 OpenAI를 호출하지 않는다. 인증·배포·내보내기는 이번 변경 범위에 포함하지 않는다.
